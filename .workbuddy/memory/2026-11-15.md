# 2026-11-15

## KotoriBlog：从「构建式静态博客」改回「零构建静态博客」

第一版做成了 Node 构建（`build.mjs` 把 md 编译成 html，产出 `dist/`）。用户否掉，两条要求：

1. 「静态就别要 node」——不要任何构建步骤。
2. 「功能很简单，首页只展示 md 文件名，不解析 md 内部」。
3. 「我博客文件是 md 啊，写哪呢」——必须把「文章放哪」讲清楚。

最终结构（14 个文件，无依赖、无 package.json）：

```
index.html / post.html / 404.html
assets/style.css assets/markdown.js assets/app.js assets/favicon.svg
posts/*.md  posts/index.txt
```

- 首页：fetch `posts/index.txt`（一行一个文件名）→ 渲染 `$ ls posts/` 文件列表，**只显示文件名**，不读 md。
- 文章页：`post.html?p=hello.md` → fetch 对应 md → `assets/markdown.js`（浏览器端手写解析器）渲染正文，标题用文件名去 `.md`。
- 加文章 = 新建 md + 在 `posts/index.txt` 加一行。
- 部署：CF Pages，Build command 留空、输出目录 `/`；或 `npx wrangler pages deploy .`。

踩坑：
- `file://` 打开会因 CORS 读不到 md，必须起静态服务（`python3 -m http.server`），页面里已写好提示文案。
- 沙箱的 node shim 拦 `fs.copyFileSync`（EPERM）；`rm -rf` 走 safe-delete 会把文件挪进项目内 `.Trash-0/`（已 gitignore）。
- bash 沙箱看不到 `.workbuddy/`（ls 里不出现），但 Write/Read 工具能正常读写——之前误以为被删。
- 截图验证用 `chromium --headless=new --no-sandbox --screenshot=...`，截图落在项目内目录才读得到（/tmp 与 bash 视图不一致）。
